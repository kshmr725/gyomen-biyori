# 魚麵日和 MVP Product & Engineering Spec

版本：0.1  
日期：2026-07-25  
狀態：訪談決策已收斂，可進入 MVP 實作

## 1. 產品目標

幫助使用者在已經決定台北某個區域、但不知道要吃哪間拉麵時，快速得到一個可信、可立即出發的單一推薦。

核心成功不是「展示最多店家」，而是讓使用者在最少決策負擔下完成：

地圖選點 → 選步行時間 → 選預算 → 選排隊容忍度 → 選新店／可重複 → 得到一間營業中的店 → 開啟導航。

## 2. 主要使用者與公開策略

- 第一優先使用者：小魚。
- MVP 可公開使用，核心推薦免登入。
- 登入後提供收藏、吃過紀錄、1–5 分私人評分與是否願意再訪。
- 第一版個人評分不公開。
- 架構保留未來擴充更多城市、多人管理與匿名群體評分的能力。

## 3. 核心體驗

### 3.1 首頁

- 品牌：魚麵日和。
- 副標：小魚的台北拉麵地圖。
- 主要入口：幫我選一間。
- 次要入口：自由逛逛。
- 視覺：日系飲食雜誌、留白、店家照片感；語氣溫柔並帶少量幽默。
- 小魚插畫只用於首頁、空狀態、載入與錯誤狀態。

### 3.2 推薦流程

1. 請求裝置定位。
2. 使用者在地圖上選點；裝置保存上次選點並提供快捷沿用。
3. 選步行時間：5／10／15／20 分鐘，預設 15 分鐘。
4. 選預算：
   - 平價：代表性基本拉麵主餐 ≤ NT$250。
   - 一般：代表性基本拉麵主餐 ≤ NT$350。
   - 不限。
5. 選排隊容忍度：不用排／30 分鐘內／不限。
6. 選「想吃新的／可以重複」，預設想吃新的。
7. 僅從目前營業中、人工資料完整且符合全部硬條件的店產生候選。
8. 有 1 間直接推薦；有 2 間從兩間隨機；有 3 間以上從綜合分數最高的前三間隨機。
9. 結果頁顯示推薦理由與 Google Maps 外部導航。
10. 使用者僅能換一次，第二次從剩餘候選中抽選。

### 3.3 沒有符合店家

不得自動放寬條件。畫面要說明目前沒有完全符合的店，並讓使用者自行選擇放寬：步行時間、預算或排隊時間。

### 3.4 自由瀏覽

- 地圖與店家清單並存。
- 地圖移動時同步顯示畫面範圍內店家。
- 預設依實際步行時間由近到遠。
- 可切換綜合推薦分數或排隊時間排序。
- 第一版不做排行榜、公開評論或社群功能。

### 3.5 店家詳情

包含：照片、價格、排隊估算、營業時間、地址、交通方式、外部導航，以及登入使用者自己的收藏、吃過、評分與再訪意願。

## 4. 推薦規則

### 4.1 硬性條件

- `recommendation_ready = true`。
- 現在營業中；資料不明一律排除。
- 實際步行時間不超過使用者上限。
- 符合價格上限。
- 符合當前時段的排隊容忍度。
- 「想吃新的」時排除使用者已標記吃過的店。

### 4.2 排隊時段

- 平日午餐：11:00–14:00。
- 平日晚餐：17:00–21:00。
- 假日午餐：11:00–14:00。
- 假日晚餐：17:00–21:00。
- 離峰：其他仍營業時段。
- 國定假日預設套用假日，可由管理員做特殊日期覆寫。

每個時段值：不用排／30 分鐘內／超過 30 分鐘／資料不足。

- 選「不用排」：只有「不用排」可通過。
- 選「30 分鐘內」：「不用排」與「30 分鐘內」可通過。
- 選「不限」：所有值包含資料不足皆可通過。

### 4.3 排序權重

匿名或個人資料不足：

- 實際步行時間：50%。
- 排隊估算：30%。
- Google／外部群體評分：10%。
- 管理員精選分數：10%。

管理員精選分數：

- 湯頭 40%。
- 麵體 25%。
- 配料 20%。
- 整體完成度 15%。

## 5. 資料策略

- MVP 地圖只顯示人工整理完成的店家。
- 我方先整理台北主要拉麵熱區候選名單，Kevin 審核店名與範圍後才進正式資料庫。
- 每間分店視為獨立店家，另保留 `brand` 欄位。
- 上線驗收以主要熱區覆蓋為主，而非固定總店數；目標是每個承諾熱區至少 3 間可推薦店。
- 店家照片由管理員上傳。
- OSM 每日只同步已收錄店家。
- OSM 營業時間可直接更新；店名、地址、座標變更進待審核佇列。
- 人工覆寫永遠優先，且需保留最後更新時間。

## 6. 營業狀態

- 來源優先序：人工特殊日期覆寫 → 人工一般營業時間 → OSM opening_hours。
- 無法解析或無資料時不得進推薦。
- 第一版僅支援「現在就要吃」，使用 Asia/Taipei 時區。

## 7. 技術架構

- Web：Next.js App Router + TypeScript。
- 地圖：Leaflet + OpenStreetMap tiles。
- 路線：openrouteservice Matrix API（foot-walking）。
- DB／Auth／Storage：Supabase Free。
- Login：Google OAuth。
- Hosting：Vercel Hobby。
- 導航：外部 Google Maps URL，不串 Google 付費 API。

## 8. 路線服務 Guardrail

- 正式推薦必須使用 route engine 計算的步行時間。
- 服務失效時先讀近期可信快取。
- 沒有可信快取時暫停推薦，只保留地圖與店家瀏覽。
- 不得悄悄改用直線距離。
- 本機 demo 可使用明確標示的估算模式；正式環境禁止啟用。

## 9. 權限

- 匿名：瀏覽、推薦、導航。
- 登入使用者：收藏、吃過、私人評分、再訪意願。
- 管理員：店家、照片、價格、排隊、精選分數、人工營業時間、特殊日期、推薦資格與同步變更審核。
- 第一版只有 Kevin 為管理員；schema 保留未來多人協作。

## 10. MVP 不做

- 公開評論與留言。
- 公開排行榜。
- LINE 登入或 Email 密碼登入。
- 任意未來日期／時間推薦。
- 自動掃描整個台北的所有拉麵店。
- 付費 Google Places／Routes API。
- 未審核店家進入推薦。

## 11. 驗收條件

1. 未登入使用者可從首頁在手機完成完整推薦流程。
2. 推薦結果必須符合營業、步行、預算、排隊與新店條件。
3. 候選規則符合 1／2／3+ 間邏輯，換一間最多一次。
4. 無符合店家時不自動放寬條件。
5. 路線資料不可用且沒有快取時，推薦功能明確停用。
6. 登入使用者可保存收藏、吃過、1–5 分與再訪意願，且資料只對本人可見。
7. 管理員能維護推薦必要資料與人工覆寫欄位。
8. 手機版為主，桌面版功能完整；後台桌面可用。
9. TypeScript typecheck、ESLint 與 production build 通過。
10. 正式上線前 seed 資料全部標記為未驗證或替換為審核後資料。

## 12. 風險

- OSM opening_hours 完整度不足：以人工覆寫與 fail-closed 處理。
- 免費 ORS 額度：Matrix 批次、快取與請求限制；超額時停止推薦。
- OSM 公共圖磚無 SLA：早期低流量使用，成長後替換 tile provider。
- 管理資料成本：以主要熱區優先，不追求一開始全台北完整。
